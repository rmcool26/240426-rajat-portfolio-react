# RMCOOL26 Work Summary

## Purpose
This file is the structured source-of-truth summary for the **homepage Work section redesign** of Rajat Mishra's portfolio.

Use this file to understand:
- what work exists,
- what should be shown first,
- what should stay visible but secondary,
- what should move to archive,
- and how to present breadth without clutter.

---

## 1) Portfolio Goal
The Work section must help a hiring manager understand, within a few seconds, that Rajat:
- has handled **websites, web apps, enterprise tools, mobile apps, and documents**,
- has worked across **multiple industries**,
- has done both **scratch builds** and **redesigns**,
- and has shipped **real work**, not just concept visuals.

### Key user behaviour to design for
- Most first-time viewers will come from **mobile**.
- Most users will scan fast and spend only **2–3 seconds per item**.
- So every work item must answer quickly:
  1. What is it?
  2. What kind of work was done?
  3. Why does it matter?
  4. Can I open it?

---

## 2) Core Rules for the New Work Section
1. **Mobile-first always**.
2. **Minimal content only** — short, clean, readable.
3. **No split between “Case Studies” and “Other Work”.**
   - This is the biggest clarity problem in the current section.
   - All work should feel part of one professional system.
4. **Breadth should be visible fast**.
   - Website work, web app work, mobile work, and document work should all be discoverable.
5. **Do not overload the default view**.
   - Show the strongest work first.
   - Keep the rest accessible by filters and archive.
6. **No fake filler content**.
   - If an old project has no screenshot or no proof, show it as archive text only.
7. **No repeated clutter from the same product ecosystem**.
   - pvNXT has many sub-products.
   - Show it smartly, not repetitively.

---

## 3) Final Showcase Strategy

### Recommended live strategy
- **Default “All” view:** show **8 curated proof items**.
- **Filtered views:** show all relevant items in that category.
- **Archive:** older website names without visuals/screenshots should stay in a compact archive list.
- **RMCOOL Thinking:** keep scope ready, but only show live if at least 3 proper assets/screens are available.

### Why this is the right balance
Showing every project equally on first load will reduce impact.
Showing only 2–3 projects will reduce breadth.

So the best balance is:
- **8 strong items for first impression**
- **all remaining work accessible through filters**
- **older/no-asset work placed in archive**

## 11) Content Style Rules for Public Cards
Every card should stay fast and scannable.

### Title
- Keep original project name.

### One-line summary
- Max **10–14 words**.
- Must explain the value fast.

### Proof chips
- Max **3 chips** visible.
- Use only useful labels: e.g. `Website`, `Web App`, `Mobile App`, `Live`, `Internal`, `Redesign`, `Scratch`, `CRO`, `GIS`, `Enterprise`.

### CTAs
- Keep only relevant ones:
  - Case Study
  - Live Site
  - Design / Figma
  - App Link
- Do not overload with 4–5 links on every card.

## 13) Short Decision Statement
If the goal is hiring impact, the homepage Work section should not try to show everything equally.

It should:
- lead with the strongest 8 proofs,
- show category breadth through filters,
- keep copy minimal,
- preserve theme quality,
- and make Rajat look like a designer who ships across formats, not just a designer with many random cards.
